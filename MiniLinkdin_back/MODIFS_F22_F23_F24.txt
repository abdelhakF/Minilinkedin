   getDashboardStats() reecrit pour calculer :
     - totaux (utilisateurs, posts, enseignants)

     - pendingSignalements (signalements PENDING)

     - postsLast7Days     (depuis aujourd'hui - 6 jours, 7 jours inclus)
     - usersByRole        (Map ETUDIANT/ENSEIGNANT/ADMIN -> count)
     - usersTimeSeries    (compte par jour, 7 dernieres entrees)
     - postsTimeSeries    (compte par jour, 7 dernieres entrees)
   Methodes privees ajoutees :
     - buildUserSeries(LocalDateTime since)
     - buildPostSeries(LocalDate since)
     - last7DaysSeries(today, byDay)  -> remplit les jours sans donnee
       avec 0 (zero-fill), garantit toujours 7 entrees ordonnees du
       plus ancien au plus recent.

=====================================================================
NOTES TECHNIQUES
=====================================================================

- spring.jpa.hibernate.ddl-auto=update : Hibernate va creer
  automatiquement les nouvelles tables (signalement, etablissement,
  domaine) et la nouvelle colonne (utilisateur.date_inscription).
  Aucune migration SQL manuelle n'est requise.

- Les utilisateurs deja en base auront date_inscription=NULL : ils ne
  seront donc pas comptabilises dans newUsersLast7Days ni dans la
  serie temporelle. Pour les "rattraper", on peut executer une fois :
      UPDATE utilisateur SET date_inscription = NOW()
      WHERE date_inscription IS NULL;

- Le nettoyage des FK lors de la suppression d'un user/post a ete
  etendu pour inclure les signalements (sinon violations de FK).

- Build verifie : ./mvnw clean compile -DskipTests => BUILD SUCCESS
  (99 fichiers source).
